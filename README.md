# CBP Data Processing

## Intro

We provide code for collecting and processing our CBP Encounters dataset. The encounters data include Title 8 apprehensions and Title 42 expulsions recorded by the United States Border Patrol (USBP) and exclude Title 8 inadmissibles recorded by the Office of Field Operations (OFO).

These pipelines collect files published by CBP, standardize their differences, identify and remove overlapping coverage when applicable, and combine the records into usable datasets.

**Note: The OFO inadmissibles pipeline and dataset are still in progress and will be updated upon completion.**

## Running the Pipelines

The final dataset, `usbp-encounters-latest.parquet`, comprises data pulled from both pipelines. While CBP's USBP encounters data was more consistent, it covers less time than the apprehensions data. The final dataset appends apprehensions data to the beginning and end dates of the encounters dataset. To reproduce our final dataset, run the apprehensions scripts and then the encounters scripts in numeric order, as `usbp-encounters-latest.parquet` depends on the apprehensions data being fully generated.

Git LFS is required to download and update large data files used by the pipeline. Several scripts have functions that require manual inputs. When CBP publishes new files, run the pipeline again, beginning with the first download script. Review all warnings and audit tables before proceeding.

## Repository Organization

The `cbp` repository contains three main folders. Throughout this document, `<dataset>` indicates the relevant dataset between apprehensions or encounters.

-   The `code/<dataset>` folder contains all project code needed to reproduce each dataset.

-   The `data/<dataset>/` folder contains all data extracted through the pipeline.

    -   `~/included-sources/`: source files accepted into the pipeline downloaded from CBP's website

    -   `~/excluded-sources/`: downloaded files excluded by the inclusion rules

    -   `~/metadata/`: inventories, crosswalks, metadata, and other information

    -   `~/processed/`: any transformed raw files

    -   `~/validation/`: validation outputs and files comparing pipeline counts with CBP published totals

-   The `inputs/` folder contains the raw PDF files provided by the Deportation Data Project to fill a gap in CBP data found in 2014

Several intermediate outputs are excluded from Git through `.gitignore` and can be regenerated by running the pipeline scripts.

### 0. Convert PDF Files

Scripts: `0-convert-pdf.R` in apprehensions

This script converts PDFs used to fill in a gap in information found in 2014 on CBP's website. We used files obtained by Deportation Data Project co-director David Hausman, represented by the Law Office of Amber Qureshi and the National Immigration Project. This script exists only for apprehensions and does not need to be rerun after the PDF files are converted to parquet form.

Inputs:

-   `inputs/pdfs/`: contains original PDF files

Outputs in `data/apprehensions/`:

-   `included-sources/usbp_apprehensions_nationwide_fy14.parquet`: combined parquet version of original PDF files

### 1. Download Source Files

Scripts: `1-download-<dataset>.R`

These scripts find source files on the CBP records pages and skip files when the same name already exists in the destination folder.

Outputs in `data/<dataset>/`:

-   `included-sources/`: contains files that meet inclusion criteria
-   `excluded-sources/`: contains files excluded by the inclusion criteria and retained for review
-   `metadata/usbp-apprehension-links.parquet` and `metadata/usbp-encounter-links.parquet`: list URLs for files selected for inclusion or manual review

Any new files that appear in `excluded-sources/` should be manually reviewed before proceeding to the next script. If you suspect CBP replaced a file without changing its name, check the source manually.

### 2. Profile Worksheets and Headers

Scripts: `2-profile-<dataset>.R`

These scripts identify the header row in each worksheet, inventory the columns in `included-sources/` files, and find all distinct column names.

Outputs in `data/<dataset>/metadata/`:

-   `sheet-inventory.parquet`: lists each sheet in included-sources/ and its source file
-   `raw-column-inventory.parquet`: records each sheet’s detected header and each column’s original name, cleaned name, and position
-   `distinct-columns.parquet`: summarizes unique cleaned column names, their original names, and how often they appear across files
-   `failed-sheets.parquet`: lists sheets that failed profiling, created only when failure occurs

By default, `force_reprofile <- FALSE`, so only files that are not already represented in the sheet inventory are profiled. Set `force_reprofile <- TRUE` when the profiling rules change, an existing raw file is replaced, or all metadata must be rebuilt. If it is set to `TRUE`, set `force_rebuild <- TRUE` in the later `4-create-parts.R` script. Review `failed-sheets.parquet` whenever it is created.

### 3. Build the Column Crosswalk

Scripts: `3-build-crosswalk.R`

This script maps variant raw headers to canonical column names and writes `data/<dataset>/metadata/crosswalk.parquet`.

Outputs in `data/<dataset>/metadata/`:

-   `crosswalk.parquet`: maps cleaned column names to canonical names and lists their original names and file counts

The crosswalk definitions are written directly in each script and require manual maintenance. Update the crosswalk whenever `distinct-columns.parquet` contains a new raw column. This script considers cleaned column names as canonical unless they are otherwise specified. After changing the crosswalk, rerun the script and set `force_rebuild <- TRUE` in the next step.

### 4. Create Standardized Parts

Scripts: `4-create-parts.R`

These scripts standardize worksheet headers and save one Parquet file per sheet in `data/<dataset>/processed/parts-to-stack/`. Each file is called a part.

Outputs in `data/<dataset>/processed/`:

-   `parts-to-stack/`: contains parts to be stacked into final datasets

By default, `force_rebuild <- FALSE`, so the scripts skip sheets that already have a part. Set `force_rebuild <- TRUE` if:

-   `force_reprofile <- TRUE` was used in `2-profile-<dataset>.R`
-   changes were made to the crosswalk
-   an existing raw file was replaced

When `force_rebuild <- TRUE`, the existing parts are removed and reconstructed. Return it to `FALSE` for ordinary incremental part building.

### 5. Stack the Parts

Scripts: `5-stack-apprehensions.R`, `5-stack-encounters.R`.

These scripts combine the remaining parts by column name.

Outputs in `data/<dataset>/`:

-   `metadata/parts-metadata.parquet`: summarizes part source files and sheets, row counts, date fields and ranges, and non-empty columns
-   `processed/usbp-<dataset>-stacked.parquet`: combines the retained parts before cleaning and overlap resolution

Before running the apprehensions stack, review `parts_to_delete` near the beginning of the script. This list is maintained manually based on overlap review. The script deletes listed files from `parts-to-stack/`.

### 6. Build Code Column Map

Scripts: `6-build-code-map.R`

These scripts create look-up tables that translate coded or truncated values into readable labels.

Outputs in `data/<dataset>/metadata/`:

-   `code-map.parquet`: code map with field, code, and full name

The mapping tables are maintained manually and should be reviewed when new coded columns or values appear in the stacked data.

### 7. Clean the Combined Data

Scripts: `7-clean-<dataset>.R`

These scripts standardize redaction codes, convert fields to their intended data types, order columns, and write the cleaned data.

Outputs in `data/<dataset>/processed/`:

-   `usbp-apprehensions-cleaned.parquet`: cleaned apprehensions dataset in final format, still containing overlapping parts
-   `usbp-encounters-final-all-cols.parquet`: cleaned encounters dataset with all columns

Apprehension parts that overlap in date are retained in this step. In using this apprehensions dataset, note that the same entry may be represented multiple times in overlapping datasets.

Several objects are maintained manually in each cleaning script and should be reviewed when the crosswalk gains new fields. Review all warnings about unrecognized values or columns absent from `column_order`. Columns not assigned another data type remain character fields by default.

### 8. Resolve Apprehension Overlaps

Scripts: `8-overlap-resolution.R`.

This script resolves overlapping apprehension datasets by using a manual list of preferred and fallback parts. These lists were built based on an investigation of usable values in key columns from each part.

Outputs in `data/apprehensions/`:

-   `processed/usbp-apprehensions-final-all-cols.parquet`: cleaned apprehensions dataset with all columns and resolved overlaps
-   `metadata/usbp-apprehensions-overlap-resolution.parquet`: summarizes source part date ranges, contribution to the final dataset, and whether they were retained

### 9. Audit the Final Data

Scripts: `9-audit-apprehensions.R`, `8-audit-encounters.R`

These scripts compare column population across the stacked, cleaned, and final apprehensions files.

Input in `data/<dataset>/metadata/`:

-   `raw-column-inventory.parquet`: lists source sheets, detected header rows, and column names and positions

Outputs in `data/<dataset>/metadata/`:

-   `final-column-inventory.parquet`: lists final columns, data types, counts of populated values at each stage, final missingness, and redaction flags
-   `raw-column-missingness-matrix.parquet`: shows the percentage of missing values for each raw column by source sheet
-   `final-column-missingness-matrix.parquet`: shows the percentage of missing values for each retained column by source sheet

### 10. Cross-Reference Datasets

Scripts: `9-cross-reference-encounters.R` and `10-cross-reference-apprehensions.R`.

These scripts compare monthly counts in `usbp-<dataset>-final-all-cols.parquet` with published CBP dashboard totals.

Outputs in `data/<dataset>/validation/`:

-   `cross-reference-files/nationwide-encounters-*-aor.csv`: CBP benchmark files downloaded from dashboards
-   `usbp-<dataset>-monthly-cross-reference.parquet`: compares monthly dataset counts with CBP dashboard counts and reports differences and match status

The `cbp_benchmarks` table is maintained manually. Before each update, check whether CBP has published a newer benchmark and add its identifier, release date, and URL.

### 12. Append Apprehensions to Encounters

Scripts: `11-append-apprehensions.R` in encounters.

This script adds apprehensions dated before the earliest encounter date or after the latest encounter date and labels rows with `record_type`. This step must be performed after `usbp-apprehensions-latest.parquet` has been generated.

Outputs in `data/encounters/processed/`:

-   `usbp-encounters-latest.parquet`, `usbp-encounters-latest.dta`, and `usbp-encounters-latest.sav`: combined encounters and apprehensions dataset in Parquet, Stata, and SPSS formats

## Updating the Data

For an ordinary update after CBP publishes a new file:

1.  Run the download script and review `excluded-sources/`.
2.  Run profiling with `force_reprofile <- FALSE` for new files. If an existing source file was replaced, set `force_reprofile <- TRUE` and then set `force_rebuild <- TRUE` when creating parts.
3.  Review new distinct columns and update the crosswalk.
4.  Set `force_rebuild <- TRUE` if the crosswalk or an existing input changed. Otherwise create only the new parts with `force_rebuild <- FALSE`.
5.  Update the manual part exclusions.
6.  Run the stacking script.
7.  Review columns to collapse in the cleaning stage and rerun the map.
8.  Clean the data.
9.  Run the dataset-specific overlap resolution, audit, cross-reference, and column selection steps.
10. Run `code/encounters/11-append-apprehensions.R` to refresh the combined encounters dataset.
11. Review warnings and validation outputs before publishing final files.
